## Git и Lovable — важные правила

- Работа ведётся в локальной ветке **`redesign`** (2 коммита поверх `main`). **Не запушена.**
- Пользователь просил: **не пушить и не мержить в `main` без явной команды.** Коммиты в `main` автоматически уезжают в Lovable.
- Из `AGENTS.md`: не переписывать опубликованную историю (no force push / rebase / amend запушенных коммитов).
- Lock-файл проекта — `bun.lock` (Lovable использует bun). Локально ставили через npm: **`package-lock.json` не коммитить** (удалён).

## Локальный запуск

```sh
nvm use          # .nvmrc = 22. На Node 20.10 Vite 8 падает (styleText / rolldown bindings)
npm install      # если node_modules ставились на другой версии Node — удалить и переустановить
npm run dev      # http://localhost:8080/
```

Проверки: `npx tsc --noEmit -p .`, `npx eslint src`, `npm run build`. После билда удалять `.output` и `.wrangler`.

В `tsconfig` включены `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes` — для опциональных пропсов, которым передаётся `undefined`, писать `T | undefined`.

## Стек

TanStack Start (SSR) + TanStack Router (file routes, `routeTree.gen.ts` генерится dev-сервером) + React 19 + Tailwind CSS v4 + Vite 8, конфиг через `@lovable.dev/vite-tanstack-config` (в `vite.config.ts` не добавлять плагины вручную — они уже включены).

## Дизайн-система

- Концепция — **типография/печать**, не «абстрактный креатив»: бумага + краска, метки обреза, цветовая шкала CMYK, растр (halftone), несовмещение красок, «печатная голова».
- Цвета (oklch в `styles.css`): `paper`, `paper-deep`, `ink`, `violet` (из логотипа), `orange` (из логотипа). **Оранжевый не использовать для мелкого текста на светлом фоне** — не проходит контраст; только заливки/крупный текст, текст поверх — `ink`.
- Шрифты (self-hosted, только latin + cyrillic, ~98 КБ): Dela Gothic One — заголовки, Onest — текст, JetBrains Mono — технические подписи (`.eyebrow`).
- Мотив из логотипа — скошенная плашка (`.plate`). Кнопки `.btn-primary/.btn-ghost/.btn-orange` со смещённой тенью.
- Анимации: несовмещение красок в H1, «печать» карточек в hero, вращающаяся печать, бегущая строка, scroll-driven reveal (`animation-timeline: view()`, без JS). Всё отключается при `prefers-reduced-motion`.
- Пользователь просил: **без AI slop** (никаких генерических градиентов/glassmorphism/эмодзи, выдуманных цифр и отзывов).

### Известные грабли

- Свои CSS-классы в `styles.css` вне `@layer` перебивают утилиты Tailwind. Не задавать в них `position`/`display` — так уже ломались `.print-in` и `Stamp`.
- У `logo.png` белый (не прозрачный) фон — в `Logo` стоит `mix-blend-multiply`. Нужен прозрачный PNG/SVG логотипа от владельца.
- Полностраничные скриншоты (Playwright `fullPage`) показывают пустые секции — это артефакт scroll-driven анимаций, у реальных пользователей всё видно. Проверять скриншотами по вьюпорту при скролле.

## Ключевые фичи

- **Карточки услуг** — картинки видны сразу (пользователь просил: не прятать за hover). Кнопка «Примерить свой дизайн» переключает примерочную.
- **Примерочная** (`TryOn.tsx`) — загрузка картинки, SVG-макеты футболки/худи/кружки/наклейки, выбор цвета, размер и положение принта. Файл не уходит на сервер (object URL). Дисклеймер «визуализация примерная».
- **Галерея работ** (`Cases.tsx`) — фильтры по изделиям, лайтбокс на `<dialog>` (стрелки, Esc).
- Карта Яндекса — фасад, iframe грузится **только по клику** (нет сторонних cookies → не нужен cookie-баннер).
- Мобильная нижняя панель: Telegram / Позвонить / Маршрут. Статус «открыто» в шапке и подсветка текущего дня.

## Фото работ — как добавлять

- Instagram без логина не отдаёт посты (API и embed требуют авторизацию). **В аккаунт друга не входить** — нет пароля и риск блокировки. Фото должен прислать владелец.
- Класть в `src/assets/cases/`. Префикс имени = категория: `tshirt-*`, `hoodie-*`, `mug-*`, `sticker-*`, `photo-*`, прочее → «Другое». Подписи — опционально в `captions` в `src/content/cases.ts`.
- Пока папка пуста: в dev показываются 4 демо-картинки с плашкой «демо», **в продакшене демо не попадает** (секция показывает только CTA на Instagram).
- Текущие `src/assets/work-*.jpg` — **AI-сгенерированные иллюстрации, не реальные заказы.** Используются как иллюстрации услуг; выдавать их за «примеры работ» нельзя. Заменить реальными фото, когда будут.

## SEO / GEO

- `lang="ru"`, один title/description на страницу, canonical, Open Graph (`og:locale ru_BY`, `og-image.jpg` 1200×630), geo-meta.
- JSON-LD в `head().meta` через `{ "script:ld+json": ... }` (TanStack). Дочерний route перекрывает `title` и `meta` корня; `links` **не дедуплицируются** → canonical только в дочерних роутах.
- `robots.txt` явно разрешает Яндекс, Google, GPTBot, OAI-SearchBot, PerplexityBot, ClaudeBot, Google-Extended.
- `llms.txt` — выжимка о бизнесе для AI-поиска. FAQ с FAQPage-разметкой — главный GEO-актив; ответы только из подтверждённых фактов.
- `SITE_URL = https://printvibe.by` — **домен не подтверждён** (сейчас не резолвится). При смене обновить `business.ts`, `robots.txt`, `sitemap.xml`, `llms.txt`.

Не юридическая консультация — финальные тексты проверить у юриста.

- Выдуманные отзывы удалены (недостоверная реклама, Закон «О рекламе»). Добавлять только реальные, с согласия авторов.
- На сайте должны быть сведения об исполнителе: **ФИО ИП / наименование и УНП** → поля `business.legal.name` и `business.legal.unp` (пока пустые; когда пустые — в футере не выводятся).
- Политика конфиденциальности по Закону РБ от 07.05.2021 № 99-З — `/privacy`. Оператор подставляется из `business.legal`.
- Аналитики и собственных cookies нет. Если добавлять Яндекс.Метрику/GA — нужен баннер согласия и правка политики.
- **Указ № 60**: сайты, через которые ИП/юрлица РБ продают услуги, должны размещаться на хостинге в РБ. Lovable хостит на Cloudflare (вне РБ) — открытый вопрос к владельцу/юристу.
